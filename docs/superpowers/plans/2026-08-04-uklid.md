# Úklid po CLI — implementační plán

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dodělat devět nálezů ze závěrečné revize CLI — hygienu argumentů a výstupu, jeden chybějící zákaz ve validátoru, drobnosti a nový kořenový readme.

**Architecture:** Žádná nová vrstva. Mění se čtyři existující soubory v `src/` (`Cli/Arguments`, `Cli/Application`, `Validator/Validator`, `Runner/Runner`), dva testy, čtyři řádky v JSON přepisu a `readme.md`. `Application` navíc dostane volitelný `ProcessRunner` v konstruktoru — je to jediný způsob, jak vůbec spustit záchytný `catch`, protože dnes tu výjimku nic nehází.

**Tech Stack:** PHP 8.1+, nette/utils ^4.1.4, nette/tester ^2.6, PHPStan level max (pokrývá `src` i `tests`).

Referenční pravda: `docs/format-specifikace.md` verze 0.3.
Návrh: `docs/superpowers/specs/2026-08-04-uklid-design.md`.

## Global Constraints

- **PHP 8.1+**, tabulátory jako odsazení, `declare(strict_types=1);` v každém souboru, dvě prázdné řádky mezi metodami — přesně jako okolní kód.
- **Nikdy `Nette\Utils\Process::runCommand()`** — jen `runExecutable()`. Interpretovaný shell je zakázaný zadáním.
- **Žádná databáze, žádný console framework** (contributte ani jiný). CLI je vlastní wrapper nad `$argv`.
- **Uživatelské hlášky jsou česky**, kód a identifikátory anglicky, `readme.md` v kořeni anglicky.
- **Tři kategorie jmen:** slovník formátu (klíče JSONu) `snake_case`; klíče mapy pojmenované člověkem `camelCase`; klíče dodané enginem VELKÁ (`STDIN`, `CWD`).
- **Návratové kódy:** `0` proběhlo celé, `1` krok selhal za běhu, `2` nespustilo se vůbec.
- **Stdout je vyhrazený** pro `--list`, `--help` a výstup kroků, které si `result` nemapují. Všechno ostatní — průběh i chyby — jde na **stderr**.
- **Nikdy neohýbej produkční výstup, aby vyhověl testu.** Když vzor nesedí, oprav vzor (`%A%` potřebuje aspoň jeden znak, na začátku hlášky se hodí `%A?%`).
- **Po každém tasku musí projít** `make test` i `vendor/bin/phpstan analyse` (level max, `src` i `tests`).
- `docs/workflows/{jpw,olw}` jsou cizí git repozitáře v `.gitignore` — nikdy je nepřidávej do commitu.
- Testy se spouští z kořene repozitáře: `vendor/bin/tester tests -C`.


Nový tvar — tři nové kontroly před dosavadní logikou, zbytek větve zůstává beze změny:

```php
		} elseif (\str_starts_with($arg, '--')) {
			$name = \substr($arg, 2);

			// pokrývá holé "--" i "--=hodnota"; obojí je klíč bez jména
			if ($name === '' || \str_starts_with($name, '=')) {

			$key = \substr($name, 0, $position);

			}
```

```php
/**
 * Pozn.: zachytí se jen to, co píše Application — tedy --list, --help
 * a chybové hlášky. Standardní výstup spuštěných kroků jde na skutečný
 * STDOUT procesu, ne do podstrčeného streamu, takže se tady ověřit nedá.
 * Od toho je přijímací test v Cli.acceptance.phpt, který pouští donut jako
 * samostatný proces přes proc_open.
 *
 * @param  array<int, string> $argv
 * @return array{int, string, string} kód, stdout, stderr
 */
function spust(string $dir, array $argv, ?ProcessRunner $processes = null): array
{
	$out = fopen('php://memory', 'r+');
	$err = fopen('php://memory', 'r+');
	$code = (new Application($dir, $out, $err, '', $processes))->run($argv);
	rewind($out);
	rewind($err);
	$result = [$code, stream_get_contents($out), stream_get_contents($err)];
	fclose($out);
	fclose($err);

	return $result;
}
```

- [ ] **Step 1: Doplň `@throws` na `Runner::run()`**

`run()` hází `CannotStartException` ze tří míst a docblock o ní mlčí. Nahraď:

```php
	/**
	 * @param  array<string, string> $initialMap
	 * @return array<string, string> výsledná mapa
	 * @throws CannotStartException neúspěšná validace nebo chybějící povinný vstup — neproběhl ani jeden krok
	 * @throws RunFailedException
	 * @throws \Donut\Parser\ParseException kámen v blocks/ se nedá naparsovat
	 */
```

```php
/** @return array{int, string, string} */
function donut(string $dir, string $bin, string $args): array
{
	// deskriptor 0 je připnutý schválně: donut si stdin čte, když to není
	// terminál. Bez toho by závisel na tom, co proces zdědil, a mohl by se
	// na čtení zaseknout.
	$descriptors = [0 => ['pipe', 'r'], 1 => ['pipe', 'w'], 2 => ['pipe', 'w']];
	$process = proc_open("php {$bin} {$args}", $descriptors, $pipes, $dir);
	Assert::type('resource', $process);
	fclose($pipes[0]);
	$out = (string) stream_get_contents($pipes[1]);
	$err = (string) stream_get_contents($pipes[2]);
	fclose($pipes[1]);
	fclose($pipes[2]);

	return [proc_close($process), $out, $err];
}
```

````markdown
# Donut

[![Build Status](https://github.com/donut-org/donut/workflows/Build/badge.svg)](https://github.com/donut-org/donut/actions)
[![Downloads this Month](https://img.shields.io/packagist/dm/donut-org/donut.svg)](https://packagist.org/packages/donut-org/donut)

<a href="https://www.janpecha.cz/donate/"><img src="https://buymecoffee.intm.org/img/donate-banner.v1.svg" alt="Donate" height="100"></a>

Donut runs workflows described in JSON files. A workflow is a list of steps;
each step runs one unix command, and the steps pass values to each other
through a flat map of strings.

These workflows used to be bash scripts calling other bash scripts. Bash has
no way to say *this step needs these values* — a mistyped variable name is an
empty string, and an empty string is a perfectly good argument. Donut declares
inputs up front, checks before it starts that every value a step reads is
written by something earlier, and refuses to run a workflow that fails the
check.

**The documentation is in Czech**, and so are the messages Donut prints.
`docs/format-specifikace.md` is the reference for the format.


## Installation

[Download the latest package](https://github.com/donut-org/donut/releases) or use [Composer](http://getcomposer.org/):

```
composer require donut-org/donut
```

Donut requires PHP 8.1 or later.


## Example

Donut looks for `blocks/` and `workflows/` **in the current working
directory**:

```
myproject/
	blocks/
		greet.json
	workflows/
		hello.json
```

A *block* wraps one command and declares what it needs:

```json
{
	"name": "greet",
	"command": "echo",
	"args": [["Hello, {%name%}!"]],
	"inputs": {
		"name": { "required": true }
	}
}
```

A *workflow* is a list of steps, with its own inputs coming from the command
line:

```json
{
	"name": "hello",
	"description": "Greets someone.",
	"inputs": {
		"who": { "required": true, "description": "Whom to greet" }
	},
	"steps": [
		{
			"type": "run",
			"block": "greet",
			"in": { "name": "{%who%}" }
		}
	]
}
```

Run it:

```
$ vendor/bin/donut hello --who=world
Hello, world!
```

And ask it what it takes:

```
$ vendor/bin/donut --list
  hello        Greets someone.

$ vendor/bin/donut hello --help
hello — Greets someone.

Vstupy:
  --who=…          povinný   Whom to greet
```

Commands never go through a shell — Donut passes arguments to `execve` as a
list, so a value containing a space, a quote or a semicolon is just a value.

Exit codes: **0** the workflow finished, **1** a step failed while running,
**2** it never started (bad arguments, unknown workflow, failed validation).
The difference is there for automation: **2** means retrying is pointless.
````
